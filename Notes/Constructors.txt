C# Constructors — Revision

A constructor is a special member of a class that is automatically executed when an object is created.

For example:

Employee emp = new Employee(1, "Harsh", 40000);

When you execute:

new Employee(...)

C# looks for a matching constructor and executes it.

1. Basic constructor
class Employee
{
    public Employee()
    {
        Console.WriteLine("Employee created");
    }
}

Then:

Employee emp = new Employee();

Output:

Employee created

The constructor has the same name as the class:

Class:
Employee

Constructor:
Employee()
2. Constructor doesn't have a return type

This is important.

Correct:

public Employee()
{
}

Incorrect:

public void Employee()
{
}

If you write void, it becomes a method, not a constructor.

So:

Constructor = class name + no return type.

3. Why do we use constructors?

The main purpose is to initialize an object's initial state.

Without a constructor:

Employee emp = new Employee();

emp.Id = 1;
emp.Name = "Harsh";
emp.Salary = 40000;

With a constructor:

Employee emp = new Employee(1, "Harsh", 40000);

Much cleaner.

The object is created with the required data already initialized.

4. Parameterized constructor

You've already used this:

public Employee(int id, string name, double salary)
{
    Id = id;
    Name = name;
    Salary = salary;
}

Now:

Employee emp = new Employee(1, "Harsh", 40000);

The arguments:

1
"Harsh"
40000

are passed into:

id
name
salary
5. Default constructor

If you don't define any constructor, C# provides a parameterless constructor automatically.

For example:

class Employee
{
    public string Name { get; set; }
}

You can do:

Employee emp = new Employee();

because the compiler provides a default parameterless constructor.

Conceptually:

public Employee()
{
}
6. Important trap: defining a constructor changes this

Suppose you write:

class Employee
{
    public Employee(int id)
    {
    }
}

Now:

Employee emp = new Employee();

❌ This won't compile.

Why?

Because once you define a constructor, C# doesn't automatically provide the parameterless constructor.

You would need:

public Employee()
{
}

if you also want:

new Employee();

So:

No constructor defined
        ↓
Compiler provides parameterless constructor

You define a constructor
        ↓
Compiler does NOT automatically add parameterless constructor

This is a very common interview question.

7. Constructor overloading

Just like methods, constructors can be overloaded.

class Employee
{
    public Employee()
    {
    }

    public Employee(int id)
    {
        Id = id;
    }

    public Employee(int id, string name)
    {
        Id = id;
        Name = name;
    }

    public int Id { get; set; }
    public string Name { get; set; }
}

Now all of these are valid:

Employee e1 = new Employee();

Employee e2 = new Employee(1);

Employee e3 = new Employee(1, "Harsh");

This is constructor overloading.

And it's the same basic principle you learned earlier:

Same constructor name, different parameter lists.

8. this keyword in constructors

Consider:

class Employee
{
    private int id;

    public Employee(int id)
    {
        this.id = id;
    }
}

Here we have two ids:

this.id → class field
id      → constructor parameter

So:

this.id = id;

means:

Put the constructor parameter id into this object's id field.

However, with properties:

public int Id { get; set; }

public Employee(int id)
{
    Id = id;
}

you don't need this.

9. Constructor chaining with this()

This is important and very useful.

Suppose:

class Employee
{
    public int Id { get; set; }
    public string Name { get; set; }

    public Employee()
    {
        Id = 0;
        Name = "Unknown";
    }

    public Employee(int id, string name)
    {
        Id = id;
        Name = name;
    }
}

There's duplicated initialization logic.

You can use constructor chaining:

public Employee() : this(0, "Unknown")
{
}

Now:

new Employee()
      ↓
Employee() 
      ↓
this(0, "Unknown")
      ↓
Employee(int, string)

This avoids duplication.

10. Constructor chaining with multiple constructors

For example:

class Employee
{
    public int Id { get; set; }
    public string Name { get; set; }
    public double Salary { get; set; }

    public Employee() : this(0, "Unknown", 0)
    {
    }

    public Employee(int id) : this(id, "Unknown", 0)
    {
    }

    public Employee(int id, string name, double salary)
    {
        Id = id;
        Name = name;
        Salary = salary;
    }
}

Now:

new Employee();

eventually reaches:

Employee(int id, string name, double salary)

So the actual initialization logic exists in one place.

This is a good clean-code practice.

11. Private constructor

A constructor can also be private.

class Database
{
    private Database()
    {
    }
}

Now outside code cannot do:

Database db = new Database(); // ❌

Why would we do this?

One common use is controlling object creation, such as certain singleton/factory patterns.

You don't need to memorize the design patterns yet; just understand:

A private constructor prevents normal external instantiation.

12. Static constructor

We already touched this in the previous topic.

class Employee
{
    static Employee()
    {
        // initialize static state
    }
}

This is different from an instance constructor.

Instance constructor
public Employee()
{
}

Runs when an object is created:

new Employee();
Static constructor
static Employee()
{
}

Runs automatically for the type, once.

Think:

Employee object
      ↓
instance constructor
      ↓
every object

Employee type
      ↓
static constructor
      ↓
once
13. Constructor vs method

This is a common interview question.

Constructor	Method
Same name as class	Can have any valid name
No return type	Has return type or void
Initializes object	Performs an operation
Automatically called during object creation	Normally explicitly called
Can be overloaded	Can be overloaded
Doesn't have a return value	Can return a value

Example:

class Employee
{
    public Employee(int id)
    {
        Id = id;
    }

    public void Display()
    {
        Console.WriteLine(Id);
    }

    public int Id { get; set; }
}

Here:

new Employee(1);

calls the constructor.

And:

employee.Display();

calls the method.

14. Constructor + properties

This is the pattern you'll use constantly in real C#:

public class Employee
{
    public int Id { get; private set; }
    public string Name { get; private set; }

    public Employee(int id, string name)
    {
        Id = id;
        Name = name;
    }
}

Then:

Employee employee = new Employee(1, "Harsh");

The object is created in a valid initial state.

This connects the three topics you've learned:

Class
  ↓
Properties
  ↓
Constructor
  ↓
Object with initialized state

🎯 Interview answer

If asked:

"What is a constructor in C#?"

A strong answer:

"A constructor is a special member of a class that is automatically invoked when an object is created. It has the same name as the class and doesn't have a return type. Constructors are commonly used to initialize the object's state. C# supports constructor overloading and constructor chaining."

One question you absolutely should know

What happens if I define a parameterized constructor but don't define a parameterless constructor?

Answer:

The compiler won't provide the parameterless constructor automatically, so new Employee() will result in a compilation error.

No. You cannot use this(...) and base(...) together in the same constructor initializer.

You can use either:

: this(...)

or:

: base(...)

but not:

: this(...) base(...)   // ❌
Why?

They both specify which constructor should run before the current constructor.

this(...) → another constructor in the same class
base(...) → constructor in the parent class
In your Developer example

You currently have:

public Developer(
    int id,
    string name,
    double salary,
    string programmingLang
) : base(id, name, salary)
{
    ProgrammingLang = programmingLang;
}

This is correct:

Developer(...)
     ↓
base(id, name, salary)
     ↓
Employee(...)
     ↓
Developer constructor body
     ↓
ProgrammingLang = programmingLang
What if you want to use this()?

You can chain within Developer first, and that constructor can then call base().

For example:

public Developer(int id, string name, double salary)
    : base(id, name, salary)
{
    ProgrammingLang = "Unknown";
}

public Developer(
    int id,
    string name,
    double salary,
    string programmingLang
) : this(id, name, salary)
{
    ProgrammingLang = programmingLang;
}

Now the flow is:

new Developer(1, "Harsh", 40000, "C#")
              ↓
this(id, name, salary)
              ↓
Developer(int, string, double)
              ↓
base(id, name, salary)
              ↓
Employee(...)
              ↓
back to Developer
              ↓
ProgrammingLang = "C#"

So you can use both this() and base() in a chain, but not on the same constructor declaration.

Remember this rule
One constructor
      │
      └── : this(...)  → same class
          OR
          : base(...)  → parent class

Not:

:this(...) :base(...) ❌

this cannot be done like public Employee(int id, string name, double salary): this(Id:id,Name:name,Salary:salary) { }
i have properties Id,Name and Salary

Correct — you cannot use this(Id: id, Name: name, Salary: salary) to refer to your properties.

This is the key distinction:

: this(...)

is constructor chaining, not property assignment.

In your code

You have properties:

public int Id { get; private set; }
public string Name { get; set; }
public double Salary { get; private set; }

and a constructor:

public Employee(int id, string name, double salary)
{
    Id = id;
    Name = name;
    Salary = salary;
}

Here:

Id = id;
Name = name;
Salary = salary;

means:

property   ← parameter
Id         ← id
Name       ← name
Salary     ← salary
But this:
public Employee(int id, string name, double salary)
    : this(Id: id, Name: name, Salary: salary)
{
}

means:

"Call another Employee constructor whose parameter names are Id, Name, and Salary."

It does not mean:

"Pass values to the properties Id, Name, and Salary."

Think of the two uses of this separately
this.Id

Means:

The Id property/field of the current object.

this.Id = id;
this(...)

Means:

Call another constructor of the current class.

public Employee() : this(1, "Harsh", 40000)
{
}

These look similar but have completely different meanings.

Your correct code
public Employee() : this(2, "hello", 9.003)
{
}

public Employee(int id, string name, double salary)
{
    Id = id;
    Name = name;
    Salary = salary;
}

The first constructor calls the second constructor.

And the second constructor assigns the values to your properties.

Employee()
   │
   │ this(2, "hello", 9.003)
   ↓
Employee(int id, string name, double salary)
   │
   ├── Id = id
   ├── Name = name
   └── Salary = salary
If you want named arguments

You can absolutely write:

public Employee() : this(
    id: 2,
    name: "hello",
    salary: 9.003
)
{
}

But id, name, and salary here are the constructor parameter names, not your property names.
