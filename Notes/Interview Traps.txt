The compiler won't provide the parameterless constructor automatically, so new Employee() will result in a compilation error.

Constructor => A constructor is a special member of a class that is automatically invoked when an object is created. It has the same name as the class and doesn't have a return type. Should every class have a parameterless constructor?
No. A parameterless constructor should be provided when creating an object without initialization data is valid. If certain values are required for the object to be in a valid state, a parameterized constructor can enforce those requirements.

# Inheritance ==================================

Does C# support multiple inheritance? => C# does not support multiple inheritance of classes, but it supports implementing multiple interfaces.

Why can this work? Employee emp = new Developer(...);
Because Developer is an Employee.

Which method executes?
emp.DisplayInfo();
Developer.DisplayInfo() because the method is overridden and dispatch is determined at runtime.

What does virtual mean?
It allows a derived class to override the base implementation.

What does override mean?
It provides a new implementation of a virtual/abstract base member.

What does base.DisplayInfo() do?
It explicitly calls the base class implementation.

What does base(...) in a constructor do?
It calls a constructor of the base class.

# Object Initialization ========================================

Object initializer => new Employee { Name = "Harsh" }

Remember this for interviews
var emp = new Employee(1, "Harsh", 40000)
{
    Department = "IT"
};

Think:

1. new Employee(...)       → constructor
2. Department = "IT"       → object initializer
3. emp is ready

So your original understanding:

"It's directly initializing properties/data members only"

is partially correct.

It does initialize the specified members directly after construction, but the constructor is still called first.

And yes, the syntax is different from manually doing:

var emp = new Employee();

emp.Name = "Harsh";
emp.Salary = 40000;

but the object-initializer syntax is essentially a convenient, compact way of doing those assignments after the constructor has executed.



# Composition Association Aggreation ===============================================


Object relationships are often explained as:

Association
    │
    ├── Aggregation
    │
    └── Composition
Association

Weak/general relationship:

Teacher ─── Student
Aggregation

"Has-a", but objects can exist independently:

Department ◇──── Employee

Employee can exist without Department.

Composition

Strong "has-a":

House ◆──── Room

Room's conceptual lifetime belongs to the House.

🧠 The easiest interview distinction

Ask yourself:

"If I destroy A, should B logically continue to exist independently?"

Yes → Association/Aggregation
University ─── Student

Student can exist after university object disappears.

No → Composition
House ─── Room

Room is conceptually part of that particular house.


# Interfaces ===============================================

Explicit interface implementation ⭐

This is an important interview topic.

Suppose:

interface IDeveloper
{
    void Work();
}

interface IManager
{
    void Work();
}

Both have:

Work()

but you want different implementations.

You can do:

class Employee : IDeveloper, IManager
{
    void IDeveloper.Work()
    {
        Console.WriteLine("Developer work");
    }

    void IManager.Work()
    {
        Console.WriteLine("Manager work");
    }
}

Now:

IDeveloper developer = new Employee();
developer.Work();

→

Developer work

And:

IManager manager = new Employee();
manager.Work();

→

Manager work

This is called explicit interface implementation.

Notice:

Employee employee = new Employee();

employee.Work(); // ❌

You can't directly call those explicit implementations through the class reference.

9. Interface vs Abstract Class

🔥 Very common interview question.

Abstract class

Use when classes have a strong IS-A relationship and you want to share common implementation/state.

abstract class Employee
{
    public string Name { get; set; }

    public void Login()
    {
        Console.WriteLine("Login");
    }

    public abstract void Work();
}
Interface

Use to define a contract/capability that potentially unrelated classes can implement.

interface IWorkable
{
    void Work();
}
Quick comparison
	Abstract Class	Interface
Can instantiate directly?	❌	❌
Can have abstract methods?	✅	✅
Can have implementation?	✅	✅ modern C#
Can have instance fields?	✅	❌
Can have constructors?	✅	❌
Multiple inheritance?	❌	Multiple interfaces ✅
Main purpose	Shared base/state/behavior	Contract/capability
Don't memorize "interface has no implementation"

That used to be a common simplification, but modern C# interfaces can have default implementations, static members, etc.

For interviews, know the modern rule.

Think:

ref → "Here is my variable. You can change it."

⚠️ One important correction to a common mental model

Don't think:

Value type     → Stack
Reference type → Heap

as an absolute rule.

That's an oversimplification.

The actual distinction is about value semantics vs reference semantics. Where a particular variable/object is physically stored is more complicated and depends on context/runtime implementation.

For your interview, focus first on the semantics, not "stack = value, heap = reference."

# Extension methods =================================================

If the interviewer asks:

"What is an extension method in C#?"

A good answer:

An extension method is a static method that allows us to add functionality to an existing type without modifying the original type or using inheritance. It is defined inside a static class, and its first parameter uses the this keyword to specify the type being extended.

And if they ask:

"How does it work internally?"

Say:

The compiler treats the extension method call as a static method call. For example, employee.PrintName() is essentially translated to EmployeeExtensions.PrintName(employee).

🧠 Remember this pattern

Whenever you see:

public static class XExtensions
{
    public static ReturnType MethodName(this X object)
    {
        // logic
    }
}

Think:

"I am adding a method-like syntax to X without modifying X."

# Tuple and valueTuple ===============================================

Q1. What is a Tuple?

A Tuple is a type that allows us to group multiple values of different types into a single object.

Q2. Difference between Tuple and ValueTuple?

Tuple is a reference type implemented as a class, whereas ValueTuple is a value type implemented as a struct. Modern C# generally uses ValueTuple because it supports named elements, deconstruction, and more convenient syntax.

Q3. How do you return multiple values from a method?
static (int Sum, int Product) Calculate(int a, int b)
{
    return (a + b, a * b);
}
Q4. What is deconstruction?
var (sum, product) = Calculate(10, 5);

It means extracting the individual elements of a tuple into separate variables.
