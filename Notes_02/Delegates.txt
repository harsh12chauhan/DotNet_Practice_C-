1. Why Do We Need Delegates?

Imagine you have a method:

C#

static void SayHello()

{

Console.WriteLine("Hello");

}
Show more lines

Normally, you call it directly:

C#

SayHello();
Show more lines

But what if you want to:

Store a method in a variable
Pass a method to another method
Return a method from a method
Decide at runtime which method to execute

That's where delegates come in.

A delegate is a type that holds a reference to a method.

Think of it as:

Delegate = Pointer to a method (but type-safe)

16. Interview Questions
What is a delegate?

A delegate is a type-safe object that holds references to methods with a specific signature.

Why use delegates?

To:

Pass methods as parameters
Implement callbacks
Support events
Enable loose coupling
Support LINQ and lambdas
Difference between Delegate and Event?

Delegate:

C#
1
public MyDelegate del;
Show more lines

Anyone can invoke it.

Event:

C#
1
public event MyDelegate del;
Show more lines

Only the declaring class can invoke it.

Events provide controlled access to delegates.

What is a Multicast Delegate?

A delegate containing references to multiple methods.

C#
1
del += Method1;
2
del += Method2;
Show more lines

Calling:

C#
1
del();
Show more lines

executes all registered methods.

What are Action, Func, and Predicate?
Action → returns void
Func → returns a value
Predicate → returns bool
The One-Sentence Summary

A delegate is a type-safe reference to one or more methods, allowing methods to be stored, passed, and invoked just like any other object, forming the foundation of events, callbacks, LINQ, and lambda expressions in .NET.
